# Experimental co-op configuration

These settings apply **only** to the `feature/coop-campaign` Server Tools
DLL. The stable R3 Server Tools release on `main` does not implement them.
All values shown are the shipped defaults in
`server-tools/KPCServerTools-default.ini`. Restart the dedicated server
after changing a switch.

| Setting under `[Coop]` | Default | Behaviour and evidence limit |
| --- | ---: | --- |
| `TraceSpawns` | 0 | Records a bounded number of actual engine position-set calls; records requested, not validated transforms |
| `TrialSeparateSpawns` | 0 | Enables fixed, map-specific R1M2B 3-player offsets only; maxclients must be 3; no general safe allocation |
| `TraceCollisionABI` | 0 | Opt-in bounded original-engine segment-query diagnostic on known R1M2B positions |
| `TracePlayerClearance` | 0 | Samples floor/body and logs fail-closed verdicts; `UNSUPPORTED` is not `SAFE` |
| `TraceBspVolume` | 0 | Whole-player-box primary-BSP classifier, hash-gated to one original 1.13 DLL; implies clearance sampling |
| `TraceModelRegistry` | 0 | Read-only named WorldModel resource and reciprocal object reference survey; implies clearance sampling |
| `TraceModelState` | 0 | Read-only raw model type/flags/vector statistics; requires `TraceModelRegistry=1` |
| `TraceCampaign` | 0 | Opt-in research trace of authored intro and campaign exit paths; not campaign synchronization |
| `CoopSession` | 0 | Co-op MVP session (kpc-coop/1): chat lobby, host start, no telefrag between players, R1M2B placements, server-coordinated changes along R1M2B → R1M2C → R1M3A (natural exits Windows-tested with one client). Written by the launcher co-op checkbox. See [COOP-MVP.md](COOP-MVP.md) |
| `CoopMinPlayers` | 2 | 1–3 players required before the host can `!start` |
| `CoopMaxPlayers` | 3 | 1–3 session capacity; keep server `maxclients` at or below |
| `CoopIntermission` | 0 | 0: change world through the native pending-NextLevel flag, without the multiplayer scoreboard. 1: native intermission (scoreboard; waits for a player's fire/use) |
| `CoopMusic` | 1 | Session only: send each player, once per map and after it spawns, the world's original music start (LOAD_STRING, TRANSITION, READY/PLAY, INTENSITY), to that client only. 0 restores the stock one-time broadcast at world initialisation |
| `CoopIntro` | 0 | EXPERIMENTAL, session only: play the world's original `starting_cinematic` once for the whole session when every present member has entered the new world (3 s settle, 30 s barrier timeout, never with zero players). R1M3A only |
| `CoopScriptClock` | = `CoopIntro` | Session only: limit the original script clock (object.lto `0xc5630`, call site `0xffba5`) to wall-clock time. The stock dedicated server credits each 8 ms frame as 10 ms (engine minimum frame time), so scripts ran 1.25× fast against the client's real-time narration. 0 = engine frame time. Engine game time is unchanged. User-confirmed on two clients (2026-11-11) |
| `CoopSoundClock` | = `CoopScriptClock` | Session only: run the server's sound timers (server.dll `0x2a1fc` → `0x29f0b`) on wall-clock time. With the inflated engine time the 44.19 s R1M3A narration was dropped from every client after ~35.9 s ("…useful ally for you"). Europe/Germany/Italy `server.dll` `83b7bce8…` only; otherwise logged and left original. 0 = engine frame time. See [COOP-MVP.md](archive/COOP-MVP-EVIDENCE-2026-11-12.md#e-narrator-cut-off-after-will-be-a-useful-ally-for-you-sound-timer) |
| `CoopStartScoreboard` | 1 | Session with `CoopIntermission=0` only: show the stock multiplayer scoreboard (`0x48`) to every member at `!start`, hold the world change 1 s, show it again after each spawn while an intro barrier holds, and close it (`0x69`) for everyone right before the intro starts. Never a click gate; never on natural exits. Not visible during the client's own world load (client limitation). 0 = no scoreboard. See [section H](archive/COOP-MVP-EVIDENCE-2026-11-12.md#h-stock-scoreboard-from-start-until-the-cinematic-coopstartscoreboard) |
| `CoopHealthBars` | 1 | Session only: enable the original enemy health-bar manager (gated to single player at `0xf8fe0`); bar data is broadcast at most 10 times per second. Stock clients draw it unchanged. 0 = stock (no bars). See [section F](archive/COOP-MVP-EVIDENCE-2026-11-12.md#f-enemy-health-bars-in-co-op) |
| `CoopSpawners` | 1 | Session only: create the map's authored monster spawners. Stock multiplayer forces them off (`0x93c5d`), which left R1M3A's `spawn6` empty. Applies to every route world; difficulty bits still apply. 0 = stock. See [section G](archive/COOP-MVP-EVIDENCE-2026-11-12.md#g-enemies-missing-after-the-r1m3a-window-smash-spawn6) |
| `CoopSkill` | absent | Session only: server difficulty written before each world load: 0 Lullaby, 1 Daydream, 2 Sleepless, 3 Cold Sweat, 4 Nightmare. Absent or out of range = unchanged (the native test server reported 2) |
| `CoopCampaign` | 0 | Session only: replace the fixed MVP route with the 48-world campaign graph from the original `WORLDORDER.TXT` (`coop_campaign.h`, checked against the user's REZ by `coop/tools/check_campaign_table.py`). Host commands, in the lobby, start at once (no `!ready`; `CoopMinPlayers` still applies): `!campaign full` (whole game from R1M0) or `!campaign water|earth|air|fire|nightmare` (or 1-5; `from <realm>` is an alias): start at that realm's first world and carry on to the end. `!campaign` alone (anyone) shows the selection and this help; anything else gets the help reply. `!start` with everyone ready still runs the current selection (default full). `!abort` (host) resets everything back to the lobby from any state: everyone returns to the lobby world, readiness is cleared and the selection goes back to full. During a world change it takes effect as soon as that world has loaded; in the lobby world itself it resets the lobby in place. Exits must lead to the WORLDORDER successor; leaving the last world of the selection completes it. Worlds missing from the native 50-entry maplist are written into the next maplist slot in memory. See [CAMPAIGN-ARCHITECTURE.md](CAMPAIGN-ARCHITECTURE.md) |
| `CoopLobbyWorld` | empty | Session: the lobby world (start, completion, `!abort`); any normalisable world path. The launcher writes it on every co-op start: the GUI passes `-Map random`, so the worker picks one of the shipped deathmatch maps PM01–PM10, starts it and lists it first in `kpc-coop-maps.txt`; an explicit `-Map` (smoke harness) is used as is. In a deathmatch world every co-op spawn rule steps aside: players use the map's own multiplayer starts. Empty (DLL default) = R1M2B |
| `CoopSinglePlayerStart` | 1 | Session only: players start at the world's single-player start. The multiplayer start strategy call (`0xf12be` → `f1070`) returns none, so the engine's own fallback picks the single-player start; the second spawn path's lookup (`0xf15f2` → `f08a0`) runs with game type 0, restored afterwards. Fixes R1M1A/R1M1B, whose deathmatch starts (9 and 16) were used. Players share the point until the allocator exists; telefrag stays skipped. 0 = stock |
| `CoopIntroAll` | = `CoopCampaign` | Session + `CoopIntro`: every route world plays its `starting_cinematic`, not only the verified ones (R?M0, R1M3A). On by default in campaign mode, because the intro scripts also preload each level's other scripts (`scriptload`; R1M1A's intro loads `r1m1a_bigdoor.scr`, which the lever plays). With it off, those scripts are refused as "not loaded" |
| `CoopIntroSettleMs` | 0 campaign, 3000 MVP | Wait after the last player has spawned before the intro starts (max 30000). The campaign default was 6000 while the client only kept its picture up; with `CampaignLoadingHoldSpawn` the players spawn when the picture ends, so the intro follows at once |
| `CoopTestStartWorld` | empty | TEST ONLY: route world `!start` loads (`R1M2B`, `R1M2C` or `R1M3A`, case-insensitive). Any other value is ignored and logged |
| `TraceMusic` | 0 | Session diagnostic: log `music-world …` when a world creates its music event (call site `0x10494b`) |
| `TraceSpawners` | 0 | Session diagnostic: log the first 64 monster spawner filter decisions (`spawner-filter skill=… miscflags=… create=…`) and per-world accepted/rejected counts in the `world-content` line |
| `CoopScriptEvents` | 1 | Session only: the five script events that return at a multiplayer gate run their single-player code (each gate is the 6-byte game-type load `mov reg,[shell+0x1d0]`): `player …` `c1a89` (teleport, invulnerable, giveitem, animate, powerup, lookat; 1040 lines in the campaign scripts), `disable_ai` `c28a5` (208), `wake_monster_group` `c269b` (17), disable targetting `c2a75`, `cheatscript` `b8ad8` (still needs the `CheatScripts` cvar). A `player` command is applied to every player in the world (`c1abe` → `f4da0` per player), not only the first. Logged as `script-event player <command> -> players=N`. 0 = stock |
| `CoopSpawnSpread` | 1 | Session only: a player whose start point is taken this world goes to the first candidate around it (96-unit grid) with a clear line from the start, a floor at the start's height (±16) and the player box clear of world BSP geometry; otherwise the start is shared. Also: a player entering a world is placed at its single-player start at once (`0xfdfdb`), so it does not fall while its spawn waits. Original `server.dll` `83b7bce8…` only. 0 = everyone at the start |
| `CoopSharedItems` | 1 | Session only: after a player's own pickup (`0xcc145` → `cc180`), a progression item is given to every other player with `f3440(player, id, 1, 1)`: weapons (item ids 3–14, UltimateWeapon `0x23`), armour (`0x27`–`0x2c`), Pamphlet `0x19`, Key `0x24`, Ticket `0x25`. Once per item object per world. Also sends the "secret found" message (`0x30c9e`) to every player (the found count is already one world counter). 0 = stock | Armour pieces (`0x27`–`0x2c`) follow the single-player rule with `CoopScriptEvents` (touch gate `0xc8348` reads 0): the touch gives nothing and the piece's cutscene `player giveitem` gives it to everyone at the single-player moment; only a piece with ReallyGiveArmor (given at the touch) is shared here. Keys and tickets come from `inventory add key|ticket` (no key objects in the campaign): its add call `0xb676f` (stock: first player only) gives the item to every player and announces `<finder> found the key (everyone has it)`; `inventory remove` still removes it from the first player only. Ammo (`0x11`–`0x14`): the amount the picker actually received (inventory count `dd190` before/after the pickup) is added to every other player with `f3440(player, id, amount, 1)` (capped by the engine at 100 + 100 per armour piece, and only with the gauntlets); firing uses each player's own count. Logged as `shared ammo=<type> amount=N`.
| (always, session) | | Cutscene view: `camera_path` moves the server view position (what the server sends to a client) of the first player only (`c2c9c` → `ef920`, reset `c2c56` → `ef950`); in a session it is applied to every player, so objects seen only from the cutscene camera reach every client. Cheats `!gimmie` (50 of each ammo + the next weapon you lack) and `!nextarmor` (the next armour piece you lack), per player, in chat; they need `kpc_cheats 1` / `AllowCheats=1` like the stock cheats and are announced |
| `CoopHostSequences` | 1 | Session, with `CoopScriptEvents`: during play only the host can start a level-ending sequence. A `CTriggerCommand` whose command list reaches the world's exit (a `trigger_generic <exit>` line, directly or through `scriptplay`/`endingscript`, e.g. R1M1A `r1m1a_victory.scr`) is reported as "not a player" to a non-host (filter `0x2e205`, ECX = trigger), so it neither runs nor is used up. Script registry `[0x1015a0b8]`/`[0x1015a0b4]`, events at script `+0x108`/`+0x104`, names at event `+0x108`; exit names per world in `coop_campaign.h`. Logged as `sequence-refused`; reply at most every 5 s. 0 = any player |
| `CoopFriendlyFire` | 0 | Session only: 0 = players cannot damage each other (hook on the damage handler's teamplay test `0xf3c08`; damage from another player jumps to `f3f1e`); self-damage and monster damage unchanged. 1 = stock |
| `CoopServerFrameMs` | 16 | Session only: minimum server simulation step, 0–50 (0 = stock). A frame call (`server.dll 235b0` → `2a05f`) sooner than this after the last simulated frame is skipped; the frame function measures its own elapsed time, so the next frame simulates all of it. Stock dedicated frames come about every 8 ms and are each simulated as 10 ms (engine floor): game time ran ~1.25× real time and physics/AI stepped like ~100 FPS, which stalls the R2M2A Ballbuster in the garage door (the same bug a KPCFix single-player client shows above 60 FPS). Europe-family `server.dll` `83b7bce8…` only |
| `TraceScripts` | 0 | Session diagnostic: `script command-play/scriptplay <name>` for every script start (command lists `0xc4238`, the `scriptplay` event `0xb8677`), `script refused <name> (already running)` (`0xc5358`), `script refused <name> (not loaded)` (the warning `c5340` prints through `f8f70`, silent in multiplayer, `0xc53a3`/`0xc53c0`) and `script switch-on <command>` when a CSwitch reaches state 2 (`0x44dd6`). At most 120 lines per world. For the R1M1A lever (`CSwitchRotating1` → `SwitchObj` → `r1m1a_bigdoor.scr`) |
| `TraceTiming` | 0 | Session diagnostic: prefix co-op log lines with `t=<ms since session armed>`; log one `clock-calibration` line (engine versus wall time over the first 10 s of frames) and, during an intro, `intro-event` per dispatched script event plus an `intro-clock` summary (and `sound-clock` when `CoopSoundClock` is installed) |

These are thirty-five `[Coop]` keys (thirteen diagnostics/test keys plus twenty-two session keys, counting `CoopIntroSettleMs`). Difficulty can also be set by the host in the lobby with `!difficulty` (overrides `CoopSkill` until the server restarts). Natural exits during play can only be taken by the host. The ninth INI-related setting
often counted in audits is `[ServerTools] AllowCheats`, a stable
hosting permission independent of co-op. `[ServerTools] Enabled=1`
is additionally required for experimental hooks.

Do **not** infer that all flags/bounds returned by the model diagnostics
identify live solid obstacles. Other WorldModels, dynamic actors,
scripted movement, triggers and map resets remain unverified.

For reproducibility capture:

```powershell
(Get-FileHash .\KPCServerTools.dll -Algorithm SHA256).Hash
(Get-Content .\SERVER_TOOLS_BUILD.json -Raw | ConvertFrom-Json).proxy_sha256
```

The first value must equal the second after installing the intended
experimental package. Capture the effective `KPCServerTools.ini`
settings, build marker and the full `KPCServerTools.log` for each
Windows observation.
